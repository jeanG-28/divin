Reprendre Divin sur vos comptes

Tout le travail fait jusqu'ici vous appartient et peut vivre chez vous, sur votre ordinateur, sur votre compte, sans dépendre de personne. Cette page explique comment, pas à pas. Comptez une petite heure la première fois.

Ce qu'il faut savoir avant de commencer. Divin est un site : chaque écran est un fichier. Il n'y a aucun programme à compiler, aucune base de données à installer. Modifier le site, c'est ouvrir un fichier, changer du texte, enregistrer.

1Récupérer le projet

Vous avez reçu un fichier divin.zip. Enregistrez-le sur votre ordinateur, puis décompressez-le (clic droit, « Extraire tout »). Vous obtenez un dossier divin : c'est le projet entier.

Rangez-le où vous voulez, mais retenez l'endroit. Par exemple Documents\divin.

Le regarder tout de suite

Ouvrez le fichier index.html : le site s'affiche dans votre navigateur. C'est déjà tout ce qui a été construit.

2Installer les deux outils

Deux logiciels gratuits suffisent, et ce sont les seuls.

Un éditeur de texte pour le code

Visual Studio Code, sur code.visualstudio.com. Installation classique, tout par défaut. C'est lui qui ouvrira les fichiers du site.

Git, qui conserve l'historique

Git, sur git-scm.com. Là aussi, tout par défaut, cliquez « Suivant » jusqu'au bout. Git ne s'ouvre pas comme un logiciel normal : il travaille en arrière-plan et c'est lui qui enverra le projet sur votre compte.

3Créer votre compte GitHub

GitHub, c'est l'endroit où le projet sera conservé, avec tout son historique. Gratuit.

  1. Allez sur github.com et créez un compte.
  2. Une fois connecté, cliquez sur le + en haut à droite, puis New repository.
  3. Nom du dépôt : divin.
  4. Laissez-le en Private si vous ne voulez pas qu'il soit visible de tous.
  5. ⚠️ Ne cochez rien d'autre : ni README, ni .gitignore, ni licence. Le projet en a déjà.
  6. Cliquez Create repository.

GitHub affiche alors une adresse du type https://github.com/votre-nom/divin.git. Gardez-la sous les yeux.

4Envoyer le projet sur votre compte

Ouvrez le dossier divin, faites un clic droit dans un endroit vide et choisissez Ouvrir dans le terminal (ou « Git Bash Here »). Une fenêtre noire s'ouvre : tapez les lignes suivantes, une par une, en validant à chaque fois.

git remote add origin https://github.com/votre-nom/divin.git
git branch -M main
git push -u origin main

Remplacez votre-nom par le vôtre. Git vous demandera de vous connecter à GitHub la première fois : une fenêtre s'ouvre, vous validez, et c'est fait une fois pour toutes.

Rechargez la page de votre dépôt sur GitHub : tous les fichiers sont là. À partir de maintenant, le projet est chez vous.

5Mettre le site en ligne

Vercel publie le site et lui donne une adresse. Gratuit également.

  1. Allez sur vercel.com et choisissez Continue with GitHub : pas de nouveau mot de passe à retenir.
  2. Cliquez Add New, puis Project.
  3. Vercel affiche vos dépôts GitHub : choisissez divin et cliquez Import.
  4. Ne changez aucun réglage. Le site est fait de fichiers simples, il n'y a rien à construire.
  5. Cliquez Deploy et patientez une minute.

Vercel vous donne une adresse, du type divin-xxxx.vercel.app. C'est votre site, sur votre compte.

6Modifier le site ensuite

Ouvrez le dossier dans Visual Studio Code : Fichier → Ouvrir le dossier, puis choisissez divin.

  • Pour changer un texte ou une page : ouvrez le fichier .html qui porte son nom. index.html est l'accueil, inscription.html l'inscription, et ainsi de suite.
  • Pour changer une couleur, une taille, un espacement : styles.css. Les couleurs du site sont regroupées tout en haut du fichier.
  • Pour changer un comportement (ce qui se passe quand on clique) : app.js.

Enregistrez, rechargez la page dans le navigateur : le changement est là.

Publier vos modifications

Dans le terminal, toujours dans le dossier du projet :

git add -A
git commit -m "ce que j'ai changé"
git push

Vercel s'en aperçoit tout seul et met le site à jour en une minute. Vous n'avez rien d'autre à faire.

Trois choses à savoir avant une vraie ouverture

Le site est aujourd'hui un prototype : il montre le parcours complet, mais il n'est pas prêt à accueillir du public. Trois points, à traiter le jour venu.

Il demande à être ignoré des moteurs de recherche

C'est volontaire, le temps de la mise au point. Deux endroits le disent : la ligne robots en haut de chaque page, et le fichier robots.txt. À retirer le jour de l'ouverture, pas avant.

La vérification d'âge est simulée

L'écran de vérification fait semblant : il attend quelques secondes et valide. Pour un service réellement ouvert, il faudra une vraie vérification.

Rien n'est enregistré sur un serveur

Les profils, les messages et les photos restent dans le navigateur de la personne. Deux téléphones ne voient pas les mêmes choses. C'est parfait pour montrer le projet, insuffisant pour un vrai service : il faudra alors une base de données.

Le dossier contient aussi un fichier HISTORIQUE.md qui retrace tout ce qui a été construit et les décisions prises, et un README.md plus court. Le site actuel reste en ligne pendant que vous installez le vôtre : rien ne s'arrête.
